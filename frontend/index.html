Algorithm Operational Mechanics

1. Greedy Vertex Selection

Extracts the unsettled vertex u with the smallest tentative distance using the binary min-heap in O(log V) time.

2. Edge Relaxation

For every outgoing edge (u, v) with weight w, if dist[u] + w < dist[v], we update dist[v], record prev[v] = u, and decrease key in the heap.

3. Backward Reconstruction

Once destination is settled, follow predecessor pointers backwards from destination to source, then reverse the sequence to form the final path.

Project Documentation & Lab Record

Comprehensive academic specifications, system architecture, viva questions, and record format.

1. Aim of the Project

To design, implement, and demonstrate a complete, robust Route Finding System that models geographical locations as vertices and interconnecting roads as positive weighted edges in a graph, computing the optimal shortest path between any chosen source and destination using Dijkstra's Algorithm implemented in C with an Adjacency List and Binary Min-Heap Priority Queue, accompanied by an interactive light-theme web frontend.

2. Data Structures Employed

  • Graph (Adjacency List): An array of vertices (Locations) where each vertex maintains a singly linked list of adjacent edges (Roads) storing target vertex index, positive weight, and directionality.
  • Binary Min-Heap Priority Queue: A complete binary tree represented as an array of heap nodes, equipped with an inverted position lookup table pos[v] to achieve O(1) node lookup and O(log V) decrease-key operations.
  • Distance & Predecessor Arrays: dist[V] stores current optimal distance from source; prev[V] stores the predecessor vertex for shortest-path backtracking.

3. Complexity Analysis

Operation Standard Array Implementation Our Implementation (Min-Heap + Adj List)
Extract-Min O(V) O(log V)
Decrease-Key O(1) O(log V)
Total Time Complexity O(V²) O((V + E) log V)
Space Complexity O(V²) (Matrix) O(V + E) (Adjacency List + Heap)

4. Dijkstra's Algorithm (Pseudocode)

ALGORITHM Dijkstra(Graph G, Source s, Destination d):
    FOR each vertex v in G:
        dist[v] ← ∞
        prev[v] ← -1
    dist[s] ← 0

    Initialize MinHeap Q with all vertices v with key dist[v]
    
    WHILE Q is not empty:
        u ← ExtractMin(Q)
        IF dist[u] = ∞: BREAK   // Remaining nodes unreachable
        IF u = d: BREAK          // Destination reached!
        
        FOR each edge (u, v) with weight w in Adj[u]:
            IF dist[u] + w < dist[v]:
                dist[v] ← dist[u] + w
                prev[v] ← u
                DecreaseKey(Q, v, dist[v])
                
    Reconstruct path backward from d to s using prev[]
    RETURN (dist[d], Reconstructed_Path)

6. Viva Questions & Model Answers

Q1: Why does Dijkstra's algorithm fail with negative edge weights?
A: Dijkstra operates on a greedy principle, assuming that once a vertex is settled/extracted from the priority queue, its shortest distance is finalized. A negative edge encountered later could produce an even shorter path to an already settled node, breaking the optimal substructure. For graphs with negative weights, the Bellman-Ford algorithm must be used.
Q2: How does using a Binary Min-Heap improve performance over a 2D matrix?
A: With an adjacency matrix and linear scan, finding the minimum distance node takes O(V), leading to O(V²) time. With an adjacency list and binary min-heap, extract-min and decrease-key take O(log V), reducing total runtime to O((V + E) log V), which is drastically faster on sparse networks.
Q3: How is Decrease-Key achieved in O(log V) without searching the entire heap?
A: We maintain an inverted position array pos[v] where pos[v] stores the index of vertex v inside the heap array. Whenever two heap nodes are swapped during heapify or bubble-up, their corresponding positions in pos[] are synchronized in O(1).
